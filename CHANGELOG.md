## [fw-v1.3.5] - 2026-10-29

Firmware only (`BrettKinny/StackChan@dotty`, submodule `c074907`). Source-only: the server address is compiled in, so build it yourself with your own `CONFIG_OTA_URL` (SETUP.md §2). Drafted with AI assistance (Claude Opus 5.5) and smoke-tested on a physical StackChan.

### Fixed
- **No reboot when the audio codec fails to open** (#196): one failed I2C read from the speaker amp while it powered up made opening the codec fail, and an `ESP_ERROR_CHECK` rebooted the robot mid-reply. Opening the speaker or microphone now tries three times, 20 ms apart. If all three fail, that audio is dropped and the next attempt to use it retries after 500 ms. While the microphone is off it reads silence, not the last buffer, and volume, gain and close errors are logged instead of rebooting. Bench (2026-10-29): the robot booted, rejoined WiFi, connected with all 15 tools, woke to the wake word and played a full spoken reply. This was one smoke test, not a soak; the I2C error is rare and did not happen during it.

## [fw-v1.3.4] - 2026-10-28

Firmware only (`BrettKinny/StackChan@dotty`, submodule `5b361e5`). Source-only: the server address is compiled in, so build it yourself with your own `CONFIG_OTA_URL` (SETUP.md §2). Drafted with AI assistance (Claude Opus 5.5) and bench-tested on a physical StackChan.

### Fixed
- **No crash when the server closes the connection** (#193): after a server-side close (the 180 s idle timeout, or an admin end-session), `~EspTcp()` skipped waiting for the receive task and deleted its event group under it, corrupting the heap (`StoreProhibited` panics about once per 50–60 closes). It now waits for the receive task to exit. Bench: 150 close/reconnect cycles with 0 panics.
- **Stays on while on USB power** (#194): the 10-minute power-save shutdown was only turned off on a battery-to-USB change, so a robot that booted on USB powered itself off 600 s after boot whenever the voice server was down. It now follows the power source from the first battery reading.
- **Servo reads no longer starve CPU 1** (#193): `SCSerial::readSCS` slept with `vTaskDelay(1 / portTICK_PERIOD_MS)`, which is `vTaskDelay(0)` at the 100 Hz tick, so polling a servo that didn't answer spun for minutes and set off the task watchdog every 10 s. It now blocks in the UART read until its timeout.
- **No power-off on a failed PMIC read**: an I2C timeout could make the power-button status read return `0xFF`, which looked like a long press and powered the robot off. Failed PMIC reads are now ignored, including in the register read-modify-writes. First reported and fixed in BrettKinny/StackChan#2, thanks @0Downtime.
- **Security sweep runs reliably** (#166): the yaw sweep ran in its own task whose stack allocation was never checked and could fail under camera + AFE memory pressure. It now runs in the motion update loop.
- **Calm when the server is down** (#180): a stopped voice server is a normal resting state, not an error with an alert sound and growing retries. The robot now stays quietly offline and retries every 120 s.
- **Head pats**: light fingertip pats register (mid level for 100 ms instead of high for 150 ms; 8 of 10 pats on the bench, up from 4), and a failed touch-sensor read counts as no touch instead of repeating the last reading.
- **Camera and wake fixes**: camera uploads own their JPEG buffer and fail cleanly when the receive task can't be allocated; a wake word is accepted on an already-open ambient channel; first speech from idle claims the talk state.

### Changed
- **The build refuses the placeholder server address**: `sdkconfig.defaults` sets `CONFIG_OTA_URL` to `http://<XIAOZHI_HOST>:8003/xiaozhi/ota/` and the build stops until you replace it, so nobody flashes firmware that can't reach a server.
- **Audio diagnostics** (#179): the boot log shows the effective AFE configuration and wake volume.

- **`POST /xiaozhi/admin/end-session`**: closes the device's listening session. Setting the state to idle or sleep from the dashboard or admin API now does the same, so the microphone closes instead of waiting for the 120 s silence timeout.
- **Overnight A/V runner can run unattended** (#182) — opt-in `--mic-opener admin_say` opens the microphone through `/xiaozhi/admin/say` before a warm case; playback is also proven by the robot's own recognition; reference-microphone slips and extra speech in the room are `INCONCLUSIVE` rather than failures; a case the evidence cannot settle is set aside after three attempts. `dotty_av_clips.py export --crop` fills the 9:16 frame from a portrait source region. See `docs/dotty-av-tests.md`.
- **Kid Mode: blocked-words content filter on the live voice path** (#157, closes the gap tracked in #138) — the pure matcher (three severity tiers + the kid-safe replacement) moved from `bridge/text.py` into the shared `custom-providers/textUtils.py`, the single source of truth both containers import; the bridge keeps its metrics/safety-ring/logging wrapper on top with unchanged behaviour. Both live LLM providers (`PiVoiceLLM`, `OpenAICompat`) now wrap their TTS-bound streams in `filter_tts_stream()`. In Kid Mode it drains and checks the complete response before TTS, then emits the original clean chunks or atomically replaces a blocked turn; outside Kid Mode it remains a transparent streaming passthrough. Full-turn consumption also prevents PiVoiceLLM from abandoning the RPC iterator before `agent_end` and leaking stale frames into the next turn. Honest caveat (see `docs/faq.md`): a word-level blocklist is a weak, bypassable backstop — prompt steering remains the primary defence. **Bench: needs on-device red-team verification before release sign-off.**
- **Admin-API auth: `X-Admin-Token` across the whole stack** (#149, #150, #151, #152) — xiaozhi-server's `/xiaozhi/admin/*` routes now accept an `X-Admin-Token` shared secret (`DOTTY_ADMIN_TOKEN`, timing-safe compare, permissive when unset), and all three callers — the bridge dashboard, dotty-behaviour's `XiaozhiAdminClient`, and the dotty-pi voice tools' `adminFetch` — send it. The secret is now **plumbed end-to-end**: `make setup` generates one into `.env`, the compose template / all-in-one pass it to xiaozhi-server, the three service compose files document where their copy lives, and `.env.example` + `SETUP.md` §10 describe the enable-everywhere-or-nowhere semantics. Previously the code shipped with no config path, so every deploy silently stayed permissive.
- **PersonResolver — one answer to "who is this?"** (`dotty-behaviour/household/resolver.py`) — identity resolution was smeared across consumers, and the 2026-06-06 audit found four separate identity bugs because of it. All resolution now funnels through one module with `Person.id` as the canonical key space. Fixed by the consolidation: **room_view roster recognition silently failing whenever `id != display_name`** (the VLM echoes display names; validation compared ids — confirmed 3/3, both the core and greeter paths), **multi-word display names never matching** (the NAME parser was single-token, so "Mary Anne" was a 100% silent miss — confirmed 3/3), **the greeter's calendar lookup dropping a person's own events on a case mismatch** (`[Hudson]` ≠ `hudson` — confirmed 2/3), and **bracketless `calendar_prefix:` YAML never matching**. `summarize_for_prompt` now matches person tags case-insensitively and accepts the resolver's tag set; the room_view test fakes were also fixed to carry real ids (the old fakes re-derived ids from display names, which is exactly what masked the bug).
- **DeviceCommand — one seam for server→firmware MCP tool calls** (`custom-providers/xiaozhi-patches/device_command.py`, mounted at `core/utils/device_command.py`) — twelve call sites across the `/xiaozhi/admin/*` handlers and `receiveAudioHandle.py` each hand-rolled the same JSON-RPC envelope, so every shared defect was twelve defects (2026-06-06 audit): request ids were `int(time.time()*1000) % 0x7FFFFFFF` (same-millisecond calls collided, with zero reply correlation to notice), and every site fired `conn.websocket.send()` uncoordinated against the other senders on the same connection. The seam owns **monotonic per-connection request ids**, **the MCP envelope**, and **per-connection serialized sends** (an asyncio.Lock — play-asset's opus frames now route through it too, so a concurrent head-turn can't interleave mid-frame). Admin handlers also share one `_dotty_resolve_conn()` instead of eight copies of the device-lookup block (which fixes the audit's `inject-text` missing-`or {}` headers nit as a side effect). Reply correlation is deliberately still absent — `call_tool` returns the request id so it can be added behind this interface without touching the callers again. **Bench: needs a live-device smoke (LED pips, head-turn, take-photo, play-asset) before release sign-off.**
- **Opt-in `sensevoice_onnx` ASR provider** (#135, builds on #124) — a new `SenseVoiceOnnx` provider (`custom-providers/asr/sensevoice_onnx.py`, type `sensevoice_onnx`) running an int8 sherpa-onnx / ONNX Runtime export of SenseVoiceSmall with **no PyTorch dependency** (~230 MB vs ~900 MB `model.pt`). It's a drop-in alternative to the patched FunASR provider for Pi-class / low-RAM hosts; FunASR stays the no-GPU default (flipping the default is a separate, benchmark-gated follow-up). Select via `selected_module.ASR: SenseVoiceOnnx`; keeps `language: en`. `make fetch-models` and `make doctor` now also download and size-check `models/SenseVoiceSmall-onnx/` (`model.int8.onnx` + `tokens.txt`).
- **Bridge systemd unit loads API keys from `${BRIDGE_DIR}/.env`** (#15) — `zeroclaw-bridge.service.template` and `scripts/install-bridge.sh` now emit `EnvironmentFile=-${BRIDGE_DIR}/.env`. `install-bridge.sh` creates a mode-0600 stub `.env` containing `OPENROUTER_API_KEY=` (and commented `VISION_API_KEY` / `VLM_API_KEY` placeholders) when one isn't already present, so the missing-vision-key failure surfaces as the bridge's existing ERROR ("camera offline") instead of a silent confabulation. Existing `.env` files are preserved.

### Fixed
- **Saved robot state survives a bad entry**: dotty-behaviour threw away every device's saved mutex state (the robot's sleep or security included) if any one device had an unexpected state, and a corrupt state file stopped the service from starting. Invalid entries are now dropped one by one and an unreadable file starts empty with a warning.
- **Kid Mode reaches vision descriptions and the greeter**: dotty-behaviour read Kid Mode from a flag nothing ever set (always off), so every room and photo description and every proactive greeting was written with the adult prompt. Both now read the shared guardian file on each use and treat a missing or unreadable file as Kid Mode on.
- **Injected turns no longer count as barge-ins** (#105): admin inject-text (the face greeter, the dashboard) and the end-of-session prompt went through the same path as speech, so injecting while Dotty spoke counted toward the four-interruptions-in-60-s close and could end a child's conversation. Only the user's own speech counts now.
- **An aborted tool loop can't spoil the next turn**: when the tool-call cap aborted a turn and pi's run did not end within 5 s (think_hard ignores the abort and can wait 90 s on a cold model), its late frames reached the next voice turn, which then said "(no response)" or "brain offline". PiClient now restarts pi in that case, and each reader thread delivers only to the queue of the process it reads.
- **Kid Mode retells think_hard answers under the rules**: the direct "think hard" route spoke the 27B reasoner's answer as-is, and since the voice rules moved into the 4B's system prompt the reasoner never saw them; only the word-level filter stood between its answer and a child. In Kid Mode the answer now goes to the 4B as context and is retold under the rules (the filter still checks it). The new context block is kept out of memory like the camera and search blocks.
- **Kid Mode danger filter blocks invitations, not facts** (#178): the imitable-danger tier blocked any listed verb near a hazard word, so "Helicopters fly using spinning blades", "Geckos can climb … ceilings", "The Little Match Girl" (`lit` matched "little") and "take your medicine" were all replaced, while "Climb up high on the shelf!" and "Grown-ups are boring, let's play with matches!" got through. A phrase now counts only when the sentence invites copying it (I/we/let's/you before the action, or a bare command); a safety cue exempts only the action it governs (a negation just before the verb, a warning after it, or asking a grown-up); swallowing hazards must be the verb's object; verb forms are exact; shelves, counters and "up high" are hazards.
- **No LAN-locked firmware releases**: pushing an `fw-v*` tag published binaries with the maintainer's server address compiled in. The firmware release workflow is now manual-only until a prebuilt can be pointed at any server (#190), and the `fw-v1.3.1`, `fw-v1.3.3-rc.1` and `fw-v1.3.3` releases are now source-only.
- **Quickstart builds the firmware from source**: step 1 told new users to download the `fw-v1.3.3` release binaries, which are compiled for the maintainer's own server and can't reach anyone else's. It now points to the build-from-source steps in SETUP.md.
- **No runaway tool loops**: with the rules in its system prompt the 4B answered "Repeat these five words" by calling `think_hard` 19 times in 30 s until the context overflowed and Dotty said nothing. `PiClient` now steers pi to answer after 3 tool calls in one reply and aborts the turn after 6, and the routing rules say `think_hard` is for hard multi-step questions only, each tool at most once per reply.
- **Kid Mode repeats ordinary words**: the jailbreak rule made the 4B refuse "Repeat these five words: purple, robot, seven, window, banana" as "part of a command to bypass my rules". Rule 7 now says repeating ordinary words is a game: say them back (mentioning spelling made it spell them out letter by letter); dangerous phrases are still stopped by rule 12 and the output filter.
- **First word no longer clipped**: xiaozhi kept only ~0.6 s of audio from before the VAD fired, so a soft first word was lost ("Do you remember…" reached ASR as "remember…"). A build-time patch (`scripts/patch-asr-preroll.py`) keeps ~1.2 s.
- **Dotty calls its tools again** (#165, #187): the ~2.8K-character tool-routing and HARD CONSTRAINTS block appended after every user turn stopped the 4B model calling tools at all; it answered "Please put on the song called tetris" without `play_song` 0 times in 6, and twice claimed actions it never took. The same rules now go in pi's system prompt (after `personas/pi_voice.md`), the user's words reach pi bare, and a Kid Mode change respawns pi with the matching rules before the next turn. The kid-mode output filter (#157) is unchanged.
- **Reproducible xiaozhi image**: the Dockerfile's pip packages were unpinned, so a rebuild could change faster-whisper or CTranslate2 underneath WhisperLocal. They are now pinned to the versions in the image that passed the 2026-10-20 A/V run.
- **No repeated line after a tool call**: after `play_song` the 4B model often said its pre-tool line again, so Dotty said "Let me play that song for you" twice. `PiClient` now holds a later agent turn's text while it only repeats the previous turn's words and drops the repeat; anything new after it is still spoken.
- **"Use your camera" takes a photo instead of inventing a room**: "Please use your camera and tell me about the room" did not match the direct camera route, and the 4B model replied "I took a snapshot and see a cozy room…" without calling `take_photo`. "Use your camera", "describe the room" and "tell me about the room" now route to `take_photo`. PiVoiceLLM's own log lines are f-strings, since loguru ignores `%s` arguments, and successful direct tools are logged.
- **PiClient log lines reach the xiaozhi log**: `PiClient` logs through stdlib `logging`, which xiaozhi-server leaves at WARNING, so `PiClient: tool call name=…` and the other INFO lines were dropped and the A/V cases could not see which tool the agent chose. They now go to the provider's logger.
- **Memory lookup survives one misheard word**: `memory_lookup` is an exact phrase search, so "the test work for tonight" found nothing for "the test word for tonight". When the phrase misses, it now retries on the query's content words and keeps only memories containing at least two of them and 60%; pending person facts stay excluded (#53).
- **No reply to a phantom "Dotty"** (#105, #164): the Whisper hotword bias turned idle servo noise into a lone "Dotty" (no-speech 0.43) and Dotty answered it. A transcript that is only the hotword now has to score no-speech 0.3 or below.
- **WhisperLocal works on the GPU after an image rebuild**: CTranslate2 loads `libcublas.so.12` by name and never found the copy in the pip CUDA wheels, so a freshly built xiaozhi image failed every utterance ("libcublas.so.12 is not found"). The Dockerfile now puts those library directories on `LD_LIBRARY_PATH`.
- **Explicit tool requests route reliably** (#165): xiaozhi's `[ROOM_VIEW]` and speaker prefixes stopped the direct tool routes matching and were written into memory. pi now runs with only the seven voice tools (no file or shell tools) and without auto-compaction, which had fired every turn on the 4B model. Camera and room views are kept out of `brain.db`.
- **`play_song` works again**: `dotty-pi` had no `XIAOZHI_HOST`, so the tool always answered "can't reach xiaozhi-server". The songs catalogue now lists and plays the MIDI songs (rendered with fluidsynth), not only `purr.opus`. A song requested mid-reply now starts after the reply finishes (`play-asset` `after_turn`); before, the reply's own speech state dropped it. **Bench: T07.**
- **Server-pushed speech is no longer dropped** (#104): `admin/say` and greeter audio were discarded by `sendAudioMessage`'s stale-turn check. Needs the xiaozhi image rebuilt (the patch is applied at build time).
- **Sticky state survives a reconnect** (#170): security, sleep and story time are restored to the device when its WebSocket reconnects.
- **Whisper hears "Dotty"** (#164): WhisperLocal takes a `hotwords` bias (`hotwords: <ROBOT_NAME>` in the template). Name corrections now apply only when the robot is being addressed, so "Goodnight Dolly" no longer puts it to sleep.
- **A storm of interrupted replies ends the session** (#105): four barge-ins within 60 s close the session instead of looping on room noise or the robot's own echo.
- **OpenAICompat follows the live kid-mode toggle**: it read `DOTTY_KID_MODE` once at startup, so a dashboard flip never reached the fallback provider. It now reads the shared toggle file every turn, like `PiVoiceLLM`.
- **Wake-word head turns stay out of dance and security**: `WakeWordTurner` had no state gate. (`SoundTurner` already ran only in idle.)
- **Face greetings only happen in idle and talk**: `FaceGreeter` only checked for a dance, so it could greet someone in security, story time or sleep. Both the bare and the named greeting now check the state first.
- **Head pets purr only in idle and talk**: `PurrPlayer` had no state gate, so it could purr over a dance or story, in security, or when a touch woke Dotty from sleep.
- **A lost face no longer cuts off a story or a dance**: `FaceLostAborter` aborted speech in any state shortly after a greeting. It now acts only in idle and talk, and checks the state again before the abort fires.
- **Dashboard State, Kid Mode and toggles stay in sync** (#169, #21): the State card and sensor staleness only judge the live robot, the Kid Mode card shows the persisted guardian policy, and the bridge pushes the toggle pips to the robot when it starts.
- **Test probe devices expire** from dotty-behaviour's per-device state, so a leftover probe no longer turns the robot's status dot amber.
- **Reading the latest photo no longer deletes it**: `GET /api/vision/latest/{device}` used to pop the cached photo.
- **Closing a dashboard tab no longer freezes the dashboard**: the perception feed relay could block the bridge for up to 15 s when a client disconnected.
- **Surprise and thinking faces render again** (#168) — the leading-face guard turned every emoji outside the nine supported ones into neutral, so a model reaching for `😲` or `🧐` showed no face change. `enforce_face_stream()` (shared by `PiVoiceLLM` and `OpenAICompat`) now maps near-miss emoji onto the supported set, keeps exactly one face, and puts it on the first streamed chunk as soon as it arrives. **Bench: confirm the surprise and thinking faces on the device.**
- **Kid Mode output filter covers every PiVoiceLLM path and fails closed** (#157, #138) — `think_hard` results reached TTS without the filter; all PiVoiceLLM output now runs through `guard_tts_stream()`. A matcher error replaces the turn instead of speaking unchecked text.
- **Kid Mode: on-topic replies and no imitable danger** (#178) — three new kid-mode prompt rules (answer what was asked, ask again when the words make no sense, never describe copyable physical danger) and a `danger` filter tier for phrases like "dancing around the fan blades". **Bench: re-run the #178 prompts.**
- **Voice: one abort no longer silences every later reply** (#176) — a device or admin abort set `conn.client_abort` and nothing on the `nointent` chat path cleared it, so ASR and the LLM kept running but no TTS was sent until the robot reconnected. `startToChat` now clears the flag when a new user turn is accepted. Reproduced and verified on the physical robot.
- **Asking about a friend always checks memory**: the 4B answered "What do you know about my friend Sam Baker?" with "I don't have any information" without calling `recall_person`. "What do you know about my friend / neighbour / teacher … <name>" now runs `recall_person` directly. Nothing known gets "I don't know anything about <name> yet", which is also what's said about a fact still waiting for review. Found by the release A/V run.
- **Named songs play** (#192): "Please put on the song called tetris" got "Tetris is a puzzle game, not a song" with no `play_song` call. "Play / put on the song (or tune) called <x>" now runs `play_song` directly, and the catalogue decides: "Here's tetris!", or "I don't have a song called <x>.".
- **The dashboard can wake a sleeping Dotty again**: an admin `sleep` closed the WebSocket, and a sleeping robot never reconnects, so `set-state idle` from the dashboard had no device to reach. Even without that close, xiaozhi's inactivity check dropped a sleeping robot after about 3 minutes. Now `sleep` keeps the connection, and the server keeps a sleeping device's connection alive. The firmware privacy gate still keeps the mic and wake word off. Found by the release A/V run (S05).
- **Server speech after an abort is no longer lost**: the same `client_abort` flag also silenced `/xiaozhi/admin/say`, so a greeting after `FaceLostAborter` or a dashboard stop never played until the next chat turn. The say route now clears the flag before queueing, as play-asset already did. Found by the release A/V run, where the mic opener's "Ready." after a song was dropped.
- **Live voice path now has a Dotty system prompt** (#177) — `PiClient` spawned pi with no `--system-prompt`, so pi's built-in coding-assistant prompt was the only identity the model saw ("I'm just a tiny coding assistant…"). `personas/pi_voice.md` is now passed via `--system-prompt` (`DOTTY_PI_SYSTEM_PROMPT_FILE` overrides; a missing file keeps the old behaviour). The persona also tells the 4B model to answer briefly and stop.
- **WhisperLocal drops near-silence hallucinations** (#105) — transcripts whose mean `no_speech_prob` exceeds `no_speech_threshold` (default 0.6, `1.0` disables) are discarded instead of being answered ("Thank you." after the robot stops speaking).
- **Memory: prompt scaffolding is no longer stored or spoken** (#186) — every voice turn was logged to `brain.db` with the per-turn tool-routing and HARD CONSTRAINTS text attached, and an explicit recall ("do you remember…") spoke `memory_lookup`'s raw rows. The turn logger now stores only what the person said, `memory_lookup` cleans older rows at read time, and recall passes the search results to the model as context so the answer is phrased naturally.
- **think_hard no longer fails on a cold start** (#187) — its request timeout defaulted to 30 s, shorter than the reasoner's 30–50 s cold load, so the first think-hard after an idle period was cancelled mid-load. Default is now 90 s (as the pre-cutover bridge unit had it), the direct tool runner allows 105 s, and Dotty says "Let me think hard about that." before the wait.
- **PiVoice RPC turns are serialized** (#175, thanks @0Downtime) — one connection can no longer interleave two pi transactions and consume each other's frames.
- **No-GPU ASR path no longer crash-loops on first run** (#124, #136) — `make fetch-models` was requesting two SenseVoiceSmall filenames that don't exist on Hugging Face (`tokens.json` and `chn_jpn_yue_eng_ko_spectral.fbank.conf.yaml`); the real SentencePiece tokenizer is `chn_jpn_yue_eng_ko_spectok.bpe.model`. Both 404s were silently saved as 15-byte "Entry not found" stubs (curl had no `--fail`), so funasr loaded with `bpemodel=None` and `xiaozhi-esp32-server` crash-looped on every GPU-less host. The file list is corrected; **all `fetch-models` downloads now fail loudly** (`curl --fail --retry` + a size floor + delete-on-failure) instead of saving junk; and **`make doctor` now size-checks the required SenseVoice assets** so a corrupt download FAILs instead of passing. Huge thanks to **[@miltieIV2](https://github.com/miltieIV2)** — a meticulous bug report *and* a self-driven root-cause that pinned it on the `HAS_CUDA=0` FunASR switch. A lighter int8 sherpa-onnx SenseVoice runtime (no PyTorch) for Pi-class hosts has landed as the opt-in `SenseVoiceOnnx` provider (#135; see the Added section above).
